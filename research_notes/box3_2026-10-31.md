# Non-cubic periodic boxes, 2026-10-31 (branch `box3` from main 9159978, main 2311937 merged)

Goal: periodic boxes of any three sides (Lx, Ly, Lz), e.g. LUNA's 3D
Kelvin-Helmholtz slab (Lx = Ly = 2, Nx = Ny cells, Lz = 16 dx), with the
cubic case bit-identical to main and no more than 1 % slower. A100 numbers:
Raven gpu1, logs in `/raven/u/uli/voronoi-cpp/build-box3/logs/`
(`time-<job>.out`, `check-<job>.out`, the job scripts next to them),
binaries `build-box3/bins/<tag>` (`base` = main 2311937, `box3b` = final).

## Decisions

**Snapping: one isotropic step.** `exact_predicates::Box(lx, ly, lz)`:
step = longest side / 2^30 on every axis, each side a whole number
`period[a]` of steps. The integer in-sphere test is then the in-sphere test
of the snapped points (an isotropic scaling); per-axis steps (2^30 on every
side) would stretch the axes differently, and the integer in-sphere test of
stretched coordinates is not the test of the points (the Delaunay
tetrahedralization is not invariant under anisotropic scaling), so topology
and geometry would disagree. Coordinates stay below 2^30 per axis, so the
exactness bounds (128-bit orientation, 256-bit in-sphere) are unchanged.
A side that is not a whole number of steps is rounded to one (relative
change < 2^-31 longest/side; `Box::side` holds the rounded sides, which
the whole pipeline uses). Sides in power-of-two ratios (2 x 2 x 1/16) are
exact; 1 x 2 x 3 becomes 357913941 x 715827883 x 2^30 steps of 3/2^30.
`snap(x, box, a) = floor(x / step) mod period[a]`, which in a cube is
`floor(x / box * 2^30) & (2^30 - 1)` to the bit (scaling by 2^30 commutes
with rounding). `delta` and `Points` carry per-axis periods; `Points` is
now a struct (view + periods) instead of a View alias.

Snapping is idempotent (grid positions snap to themselves) when step * k is
exact, e.g. for 1 x 2 x 3 (tested); for sides with long mantissas (a cube
of side 0.1 or 1.7) some grid positions snap one step lower, in main as
before: unchanged, not a new limitation.

**Cell list: tiles, no padding.** The box is cut into tiles[a] =
round(side[a] / shortest side) near-cubes; each tile is an octree of
2^levels base cells per side, and a key is the tile number (row-major)
above the Morton key inside the tile. So unequal sides need no padding to
a power-of-two cube (a 512 x 512 x 16 slab padded to a cube would need a
dense offset table of 512^3 = 134M entries for 4.2M particles; tiles give
32 x 32 x 1 tiles of 16^3 cells = 4.2M entries, the cubic density). Levels
are capped so that keys fit 64 bits, cell numbers and grid coordinates an
int (`configure` throws for a box elongated beyond that, ~2^24 tiles). A
cube is one tile: the same keys, offsets and slots as main. The walk (both
kernels) uses per-axis cell counts (tiles[a] 2^level), widths (side /
tiles / 2^level, the smallest for the stencil's distance bounds) and
periodic images, and limits its reach by the shortest axis. Measured: the
slab rebuild runs at the cube's rate (below), so tiles in row-major order
cost nothing measurable; a Morton order over tiles was not needed.

**Thin slabs: reject, do not chase images.** A cell is certified only
within one periodic image: the walk never visits a grid cell twice, so
its reach is at most (cells across the shortest side - 1) / 2 cells;
the largest certifiable reach 2R is 3/8 of the shortest side (reach 3 at
8 cells across), i.e. a cell radius below 3/16 of it, and the starting cube
is 1/4 of the shortest side. Such cells come out `uncertified`, and
`voronoi::Mesh` throws "N cells reach too far to be certified in one
periodic image (a cell's radius must stay below about 3/16 of the shortest
box side): too few particles across the box". In practice: about 8 or
more particles across the shortest side (64 x 64 x 8 jittered passes, a
2 x 2 x 0.25 slab of 32 x 32 x 4 is refused, tested); the KH slab's 16 is
fine. Multiple images were not implemented: they would need the walk to
visit cells twice with different shifts and a uniqueness argument for the
cuts, for a case (fewer than ~8 particles across a periodic direction) a
hydro run would not use.

**Interface.** `voronoi::Mesh(exec, const exact_predicates::Box&)`, and
`Mesh(exec, double)` for a cube (the hydro branch compiles unchanged).
`sides()` returns the Box; `box()` stays a double for a cube and throws
`std::logic_error` for a non-cubic box (hydro-stage1 uses it as the cube's
side). `exact_predicates::Box` converts implicitly from a double, so every
`double box` parameter became `const Box&` without touching the callers.

**Cubic speed.** The first version (3ab8b5d) cost the warp rebuild 1-2.3 %
(job 31702554: uniform -2.25 %, lattice -1.40 %, jittered -1.05 %): per-axis
sides, tile numbers and wraps in the walk's inner loop. The plain rebuild
kernels now have a compile-time `cubic` case (Grid::cube(): one tile, equal
sides) with main's arithmetic; the ring and local kernels and the
per-thread kernel use the general walk (start time unchanged).

The rebuild runs at the cube's rate per cell. The steps are not comparable
with the cube's: the bench flow is periodic in the box, stretched with it,
so it varies across the slab's thickness (16 cells) and shears 4x more:
0.124 flips per cell per step at 0.03 spacings against 0.029 in the cube
(519k flips at 4.2M vs 61k at 2.1M). Per flip the repair costs the same.
The start patches a few cells in the slab (none in a jittered cube):
rounding-level ring disagreements; it is exact after the second round.

## Tests added

- `exact_predicates`: Box rounding (2 x 2 x 1/16 exact, 1 x 2 x 3
  rounded), a cubic Box snaps as the cube's snap, per-axis wrap and
  periods, 1 x 2 x 3 grid positions snap to themselves, orientation and
  in-sphere across the thin side of a slab (same signs as the copy shifted
  inside).
- `start`: jittered and an exact sc lattice in a 1:1:0.125 slab (32768),
  uniform and an exact bcc lattice in a 1:2:3 box, against the oracle
  (triangulation, box volume = product of periods, empty circumspheres).
  The oracle's emptiness scan now visits only particles whose x lies
  within the circumradius (sorted by x; all when that spans the box):
  start test 19 -> 12 s on one core with the 32768-particle cases added.
- `repair`: uniform in a 1:2:3 box (0.3, 3 steps), jittered in the slab
  (32768, 0.3, 2 steps), against an exact rebuild.
- `voronoi_mesh`: a 1:2:3 box (exact, volumes fill it, `box()` refuses
  it), a slab 4 cells thin refused with the certification error.
- `support`: `make_points(kind, n, box)` (lattices with about equal
  spacings per axis, `lattice_sides`), `scaled(points, Box)`,
  `to_grid(points, box)`, `Flow::advect(points, d, box)`, box-aware
  `check_cells`, `compare_with_rebuild`, `cell_list`, `in_slot_order`.
- `voronoi_bench --box=Lx,Ly,Lz` (both modes).
