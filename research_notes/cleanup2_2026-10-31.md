## Per item

### C0. One snap for any box (f2b9a56)

`exact_predicates::snap(x, box)` (wrapped into [0, 2^30)) and
`snap(exec, x, box, point)` replace `tet_start::snap` and
`tet_repair::detail::snap`; the latter ignored the box, so for box != 1 the
repair worked on another grid than the start. Tests: snap for boxes 1, 2,
3; start in boxes 3 (jittered) and 2 (lattice); repair in box 2.

### Warp kernel records face rings; faces in a pool (67ed31e; D1)

Lane l knows the ring lengths of its owned faces after the face walk; an
exclusive scan sizes the block, lane 0 claims it, each lane walks its
faces again to write rings in the thread kernel's plane order. The start
went 307 -> 118 ms (clip with rings 246 -> 57 ms; job 31691189), steps
unchanged, peak unchanged. Owned faces (neighbour, area, centroid) moved
from 32 slots per cell into a pool (10 per cell + a block per warp): plain
rebuild 1792 -> 701 B/cell; no owned-face limit, no widening; pools that
turn out too small grow and the build reruns (`Cells::needed`).

### Clipping consolidation (f449d73, e68e770): gate failed, adapted

Plan: the exact kernel of tet_start as the only per-thread kernel. Gate
(job 31691653/54): as the warp fallback it cost uniform -1.6 %, clustered
-3.9 %, halo -9.5 % (void and overflow cells are slower exactly, and the
fallback pass waits for its slowest cell); on all cells (thread variant)
it is 1.9-2.2x slower on random input and 13x on a lattice (exact ties).
So instead: one per-thread kernel over two cell kinds, `RoundedCell` (the
former thread kernel's arithmetic; portable kernel and warp fallback) and
`ExactCell` (start patch), sharing walk, cut topology, plane compaction,
face walk and output. `Real` is gone (double only). tet_start lost its
copy of the clipping: 561 -> 215 lines. A later profile (job 31693970)
showed the rounded fallback at 2x its old time because every cut loaded
the candidate's particle id; slots during the walk and one translation
after it (f32c909) restored it (halo fallback passes 17.3 + 16.8 ms ->
9.0 + 7.4 ms, base 8.7 + 6.9 ms, job 31694144).

### D3: particle ids (50a74eb, c69fc1c)

The clipping writes particle ids (outputs, faces, rings), applies the owner
rule and the perturbation to ids; slots stay inside the walk. tet_start
snaps by particle. So from_rings, the check, the repair and the faces use
the caller's numbering. The warp kernel translates its planes' slots once
after the walk.

### voronoi::Mesh (f873a38, c31c3ff, f7abc1a)

`update(x [, active])`, `rebuild(x)`, `clip(x, cells)` (local rebuild with
the owner rule extended to unlisted neighbours, `shell_voronoi::Selection`),
faces, volumes, `update_cells()` (per-cell face lists in increasing id of
the other particle, volumes and centroids summed in that order: bit
reproducible), `scratch(bytes)` (the spare ring pool), `Fallback`.
Positions are snapped inside; geometry comes from the snapped positions,
which removes the "positions must sit on the grid" limitation.
`support::MovingMesh` is gone; the repair test and the bench run on the
class; new CTest `voronoi_mesh`.

Per-cell face lists: computed on demand, 12.6 ms at 2.1M, 90 ms at 256^3
(counts by atomics, scan, fill, per-cell sort and sums); first version in
every update cost 11 ms per step, so it is not part of `update()`.
Memory ~141 B/cell (2 ints per face plus 1/4 slack, start and cursor, the
centroids); at 256^3 the peak with them is 2200 B/cell (36.9 GB Kokkos,
37.9 GB in use), leaving ~4 GB (~240 B/cell) of the ~42 GB usable.

Face order: faces are numbered by the tetrahedra that represent them;
`from_rings` emits tetrahedra in owner order, so with a spatial particle
order the faces start out nearly owner-sorted (no extra cost); repairs
reuse slots and slowly mix it. Not enforced.

### Repair livelock on one thread (0dbcada)

The CPU repair test took > 900 s on one core: on a lattice's first step
the device repair (run on one OpenMP thread) did 1000 rounds of ~8000
plans with almost no progress. Plans voted with their index; on one
thread the work list comes in space order, so the same pattern won every
round. Votes are now a bijective hash of the index: 56 rounds. CPU ctest
on one core: 45 s in all (exact_predicates 0.1, clipping 15, mesh 0.6,
start 19, repair 10, voronoi_mesh 2).
