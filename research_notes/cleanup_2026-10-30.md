# Cleanup 2026-10-30 (branch `cleanup`)

Goal: keep only what the mesh pipeline needs, with clear module boundaries,
identical results and no speed loss. Everything removed is preserved on the
branch `archive/codex-era` (= main at e7aac95).

## Removed

- Table pipeline: `local_voronoi*.hpp` (9 headers), `cooperative_clip.hpp`,
  `team_cell_storage.hpp`, `fixed_point_positions.hpp`; their 13 checks and
  benchmarks (`table_mesh_check`, `construction_scaling`, `neighbor_benchmark`,
  ...), `python/`, `pyproject.toml`, `docs/`, `HANDOFF.md`, 20 Slurm scripts, the
  Ruff CI job.
- Cell list: radius tables, row sorts (insertion/bitonic), lane-parallel fill,
  stage profiles, radii, non-cubic grids.
- Clipping: the lean kernel (`shell_voronoi_lean.hpp`, slower than the warp
  kernel everywhere: 10.4 vs 18.7 M cells/s jittered) with its warm start
  (Seeds); `SHELL_WARP_TEAM` (16/8 lanes, 2x/3.6x slower), `SHELL_WARP_BLOCKS`
  (non-persistent launch), `SHELL_WARP_PHASES` timers, `SHELL_WARP_MIN_BLOCKS`
  macro (now a constant), `Cells::all_neighbours` and `phase_cycles`. No
  `std::getenv` remains in the library.
- Mesh: `face_geometry.hpp` (geometry from particle rings; the parts tet_mesh
  used moved there), `faces_from_edges` (walk every edge, superseded by face
  rings), `orientations`; the plain `tet_repair::move` (all tetrahedra dirty);
  host-only `tet_flips::make_mesh`, `snap`, `neighbours`.
- `shell_voronoi_check.cpp` (1443 lines) and its modes `cullstats`, `faces`,
  `topology`, `evolve`, warm rebuild, host-only `flips`.

Shared instead of duplicated: one stencil builder; `position`, `far_vertex`,
`sorted_face`, `walk_edge`, `wrap` (tet_mesh) used by the check, screening,

its cavity, the device leaves that to the host.

## API changes

- `neighbor_search::DenseCellSearch` -> `CellList`; `configure(list, n, box,
  cell_width)` (cubic box, set `list.morton` before), `build(exec, list, x)`;
  `shell_voronoi::make_grid(list)`.
- `shell_voronoi::construct(exec, grid, out)` builds all cells (no
  `only_failed`); `construct_warp` uses the thread kernel when
  `out.rings` is requested (the warp kernel never recorded rings).
- `tet_repair::repair(exec, mesh, state)`; stuck entries in `state.stuck`,
  their count in `Stats::stuck`. `move` removed; `move_screened` is the way in.
- `tet_flips::Mesh` holds host views (`vertex`, `adjacent`, `alive`, snapped
  `point`, `count`); `repair(mesh)`, `failing(mesh)`, `to_host(dm, state)`,
  and `finish(exec, dm, state)`: the device-host round trip (marks changed
  tetrahedra touched, re-represents edges around them, keeps the device free
  list). This glue used to live in the test program.
- `tet_mesh::Geometry` (was `face_geometry::Geometry`), `tet_mesh::pad`.
- Tests: `exact_predicates`, `clipping`, `mesh`, `repair` (CTest, ~15 s on
  one CPU core). Tool: `voronoi_bench rebuild|step` with flags instead of
  environment variables (`--morton`, `--width=`, `--verify`, `--debug`).

## Behaviour differences

- The step driver now builds face rings after the host fallback. On main the
  verify mode built them before, so steps with stuck triangles showed volume
  errors up to ~1 (4096 jittered, 0.3 spacings: steps 1, 3, 9; 262k: step 7,
  0.078). Now every step matches an exact rebuild to ~1e-14.
- The starting tetrahedra come from the thread kernel's rings (main used the
  lean kernel), so tetrahedra are numbered differently and flip counts per
  step differ by a few; the triangulation is the same.
- The step timing pads positions into a preallocated view once per step;
  main allocated a padded copy twice per step inside the timers.
