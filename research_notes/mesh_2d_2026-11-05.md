# The 2D mesh (2026-11-05)

Files: exact_predicates_2d.hpp, polygon_clip.hpp, tri_mesh.hpp, tri_repair.hpp, tri_finish.hpp,
voronoi_mesh_2d.hpp; test src/test/mesh2d_test.cpp; bench src/bench/mesh2d_bench.cpp. The 2D hydro and
Kelvin-Helmholtz are in luna-cpp, research_notes/stage2_2d_2026-11-05.md.

Differences from the design note, and why:
- One polygon kernel, exact at every decision (filter, then i128, then perturbation). No rounded pass,
  no patching: cells agree by construction. The start is clipping + triangles + the screen + repair (finds nothing).
- Face numbers are for good: exactly 3n, a flip gives its face new particles. Per triangle: corners, apexes
  (screen reads no neighbour row), adjacent, faces.
- Screen fused with the circumcentres: the in-circle filter shares its products with the centre.
- Geometry is a function of the positions alone: corner 0 is the lowest id, a face is computed from the
  side of the lower apex. A repaired mesh equals a fresh build bit for bit. One `Circle` definition, else
  FMA contraction differs between kernels.
- volume() current after update_cells() only (no atomic sums in update()): a small contract difference to Mesh<3>.
- The owner's design decision 5 said device rebuild only; the stage brief asks for a host fallback: tri_finish.hpp
  (patch re-triangulated, accepted if it has the boundary edge for edge).
- Same reach limit as 3D: a cell's 2R below 3/8 of the shortest side.

Bug worth remembering: an edge may be listed twice; both entries then hold every lock. The first lock is
taken by compare-exchange.

Later bug: Morton numbers kept 8 bits, so N >= 512 lost cells (the small oracle cases never reach level 9): a 2^20 test now.

## Cell lists

The 3D path, shared: tet_mesh::detail::begin_incremental / finish_incremental (sorted kept entries, fresh faces appended,
marked cells sorted, CellSumsWarp's 4-lane sums, the n/5 limit). 2D gives it a table that is the identity except -1 for
flipped faces, and each flipped face as a fresh one. Ring append has no 2D counterpart: there are no rings. Step, jittered,
Morton-free order, one job (31919802, ravg1151, 1305 MHz), M cells/s before -> after:
2^20: 0.03 626 -> 767; 0.1 629 -> 766; 0.3 617 -> 746. 2^24: 0.03 773 -> 1026; 0.1 768 -> 997; 0.3 776 -> 1002.

## Refusals, as Mesh<3>

Particles on one grid position have no bisector: the clipping fails, and the refusal names the pair
(`detail::coincident`, shared with 3D, host, only after a failure). A refused update leaves no mesh and the next builds;
no particles are an invalid_argument that changes nothing; update_cells() without a mesh says so.

A repair can end with every local test passing on a mesh that covers the torus several times (x -> 2 x: all triangles
positive, four covers). 3D sees that in the total volume. 2D has no volumes in update(), so the screen sums the signed areas
in the kernel it already runs; a flip of two positive triangles keeps the sum, and a separate kernel
(tri_repair::total_area) runs only after an inversion or a host patch, when the screen's sum no longer holds. Off by more
than 1e-6: a rebuild, `Report::overlapped`.

Also fixed by these: a change of n kept the old face table of the incremental lists.
